# Terrain format evidence

Scope: the supplied modified campaign corpus, 99 Components maps; 90 contain terrain. The installed Editor executable reports 5.0.15.98370. This is not a complete audit of its menus, nor runtime acceptance of these writers.

The corpus audit is generated by `sc2-terrain.py scan --audit`, not committed as copied maps. Retain its component hashes with experiments. All 90 terrain maps pass byte-identical no-edit roundtrips for the eleven fixed-name formats plus present CellAttribute bitsets (1,121 component checks in the supplied corpus).

## Observed layouts

| Component | Observed format and implementation boundary |
|---|---|
| `t3Terrain.xml` | Versions 113/114/115. Descriptor includes dimensions, quantization, texture slots, cliff cells, ramps and optional terrain objects. The restricted v115 island stamp updates cliff cells with its companion grids; arbitrary topology and ramp writing remain unsupported. |
| `t3HeightMap` | HMAP 101; 32-byte header, 6 bytes per vertex: two uint16 height channels and a mask. +1.0 relative raises in both channels have scoped Editor evidence. Do not equate channel names in external notes with complete brush semantics. |
| `t3SyncHeightMap` | SMAP 102; 64-byte header and interleaved 4-byte records in every sample. Signed Q8 height and a retained uint16 companion match masks in samples. Do not treat the two channels as separate contiguous grids. Relative sync deltas remain experimental. |
| `t3SyncCliffLevel` | CLIF 100, 32-byte header, uint16 per cell. Values are not direct Editor cliff numbers. The accepted isolated-island stamp copies the donor's matching levels; general cliff generation remains unsupported. |
| `t3TextureMasks` | MASK 102, 64-byte header; eight tiled nibble planes. A 64×64 tile has 2048 bytes; even X uses the high nibble. Corpus mask dimensions are eight samples per terrain cell. |
| `t3SyncTextureInfo` | RTXT 100/101, terminated texture names, 4/8-byte cell records. Preserve the second field. Mask channels select slots within a block's texture set. |
| `t3CellFlags` | LFCT 101/102, dimensions at byte 24, payload at 32. Named visibility/foliage semantics need controlled Editor pairs. |
| `t3Water` | WATR 110. All samples have zero body records; entries contain a 40-byte configuration name and four floats forming a rectangle. The rectangle does not encode water height/state. |
| `t3FluffDoodad` | DLFT 103, 28-byte header and 9-byte records. Local records decode to float XY plus a byte. Preserve observed flags and use visibly confirmed profiles; record priority affected the accepted Zerus scatter result. New entries precede existing ones. |
| `t3HardTile` | HRDT 102, variable groups with 58-byte records and terminated names. Local positions are floats. Native straight two-endpoint road profiles can be reused with new grounded endpoints; general curves and width/material changes remain unsupported. |
| `t3VertCol` | VTCL 103/104, variable records and opaque sub-buffers, retained byte-identically. Field names from external notes do not establish their visual meaning. |
| `CellAttribute_*` | Count-prefixed bitsets in the observed files, eight storage bits per world cell. Cpl creep, Vbl vision-blocker and Pnp no-ground-path whole-cell writers have scoped Editor evidence. Manual no-ground-path painting changed Pnp bytes at (51..52,67..68) from zero to 142/43/212/113. The Pnp writer's whole-cell 255/0 result passed the PathingWrite save/reopen comparison; native finer sample ordering remains unmeasured. Preserve partial patterns outside selected cells. |
| `LightingMap.tga` | Seventeen supplied maps use uncompressed 32-bit BGRA TGA, with image origin and footer retained. Manual MarSara region-2 painting confirms G weights against default R, with four pixels per world unit and top-origin storage. The writer paints/restores those two regions in an existing raster with scoped Editor acceptance. Other channels/definitions require separate proof. |
| `MapInfo` | Known core fields in versions 31–39 are inspected. Bounds edits preserve the suffix and update the integrity-hash delta. Dimensions/cropping and player/start-location linkage remain unsupported. |

Byte-identical serialization proves retention, not semantic correctness. Finite coordinates, magic/version, payload sizes, companion dimensions and changed component names are checked before publication.

## Source reconciliation

Primary technical reference: [Talv-derived format research](https://github.com/sc2-arcade-watcher/sc2-file-format-docs). The local corpus resolves some discrepancies in field layout or interpretation. Do not copy reverse-engineered in-memory integer names into a wire decoder without checking actual bytes.

The [height notes](https://github.com/sc2-arcade-watcher/sc2-file-format-docs/blob/main/t3heightmap.md) distinguish quantization channels from geometry transforms. Accordingly the preview exposes reconstructed height. Absolute set remains blocked; uniform copies an existing sampled channel value on the same cliff level and updates sync deltas.

The [water notes](https://github.com/sc2-arcade-watcher/sc2-file-format-docs/blob/main/t3water.md) describe both body and entry sections. The current writer handles only the locally observed zero-body v110 variant; unknown layouts fail before writing.

The [MapInfo research](https://github.com/sc2-arcade-watcher/sc2-file-format-docs/blob/main/mapinfo.md) supplies the dimensions/bounds integrity relation. Changing only bounds permits a delta update without guessing player/variant suffix fields.

For terrain textures, terrain objects and other catalog assets, query the actual target graph using `sc2-catalog-query.py` and the bounded reference tool. Existence in the sample corpus or exported XML does not establish target availability.
