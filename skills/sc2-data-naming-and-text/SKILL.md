# 数据命名与说明文本

1. 明确显示位置和消费字段。分别列出内部 ID、编辑器 Name/EditorPrefix/EditorSuffix、玩家 Name/Tooltip；查询目标项目附近对象、命名空间和活动依赖。
2. 按[用途与案例](references/writing-patterns.md)选参考。用[来源记录](references/score-cases.json)查原文、声明和文件指纹。案例的数值与标记属于来源包。
3. 从目标有效数据确认主体、作用、目标、条件、数值、持续时间、叠层和限制。每项说明保留依据；无法确定的项目列为待核对。
4. 给出名称、说明草案、对应对象与键，以及采用该写法的理由。修改时加载 [Catalog 技能](../sc2-catalog-xml/SKILL.md) 和 [本地化技能](../sc2-localization/SKILL.md)，沿其入口维护 XML 和字符串锚点。

内部 ID 使用目标项目已有的 ASCII 命名约定，明确角色与作用域。SCORE 的包标记 C/G/I/M/P/D/U/W/PZ 可作为检索案例。目标的命名空间、同名覆盖和支持对象的对应关系决定新 ID。

玩家文本先说发生的变化。招募条目写定位和主要能力；主动技能写作用与限制；被动、升级写变化；状态栏行为写当前影响。内部辅助行为使用便于编辑者检索的名称与说明，按 UI 标记核对其可见性。

保留颜色标签、换行与动态引用原文。改变动态数值引用前核对其目标 Catalog、对象和字段，继承值与目标地区字符串分别查询。项目未提供模板时用简洁草案，并标明待核实项。

完成时核对名称与作用一致、Tooltip 与数据一致、标记完整、引用可解析、地区键对应。原始来源中的缺词、混合语言或疑似语义错误放入问题案例，修正目标项目需另有数据依据。
