# SC2肉鸽机制专用技能

整理或导出项目天赋清单时先用[肉鸽天赋清单导出](../sc2-roguelike-talent-export/SKILL.md)，再以其中的来源、字段和诊断定位机制审计范围。

## 新增机制

写出玩家从哪里获得、资格与互斥、一次能拿几层、持有上限、作用玩家、何时触发或消费。分别说明潜地或变形、阵亡、进入下一关和重开周目时，单位效果与玩家持有量如何处理。选一个正常领取和一个容量不足的例子，把预期写成可观察的数值。

固定属性和武器修改先查有效物编升级及其消费对象。抽取、选择队列、货币和一次性奖励先查 GUI。混合实现指定一处维护持有量，再按各效果的契约施加。沿实际项目的 Bank 键恢复玩家状态，按当前地图重新建立持续效果。

例如，设计一项最多五层、每个新领层发一次资源并提升一级武器的天赋。若项目规则允许部分领取，已有一层再领三层，GUI 记录四层、发三份资源，物编最终升到四级。已有四层时同样操作，只发一份并升到五级。跨图恢复四层时检查武器最终为四级，一次性领取奖励发放次数为零。将例子中的数值替换为本项目设计后再实施。

## 公共系统故障定位

| 玩家操作 | 需要跟踪的值与边界 |
|---|---|
| 重抽后选项消失或次数被扣 | 构造一次剩余重抽、当前池无其他合格候选的场景。比较操作前后的候选 ID、次数、队列、暂停与输入状态。按项目回退规则扫描；以有效新选项提交为扣费点。仍有旧选项时保留可用选择，首次抽取即为空时走队列结束与恢复入口。 |
| 点击购买或冻结后切图 | 连续两次购买同槽，核对商品身份、余额、持有上限和已购状态，记录实际扣款和授予次数。冻结后以该存档进入下一关，比较有效槽位、商品与容量。 |
| 多重奖励或切图后再次领奖 | 跟踪发奖事件、状态消费和重复回调，分别统计持有量变化、有效领取次数、最终单位数或资源。 |
| 读档后属性漂移 | 对同持有量分别测试领取、跨图重建、同图再次初始化，核对一次性资源和持续等级。Bank 编码与旧档往返测试见下方 Bank 技能。 |

## 条目审计与验收

先固定主组件、活动依赖顺序、语言和相关源指纹。全表审计按当前 UserData 实例顺序建清单，标出默认、禁用、指定授予和旧档入口。汇总预期数、实际数和遗漏 ID。单条诊断只展开该条及共享函数的调用方。

1. **查获取路径。** 从实际选择、商店购买、职业授予或地图奖励追到资格判断。记录作用玩家、品质、前置、互斥、上限、可用容量与本次实际新增层数。用正常入口能形成的组合复现，修改品质制造的用例只能验证局部分支。
2. **找齐消费者。** 分别用实例名、升级 ID、GUI 参数或变量追踪。对照当前 GUI 与只读生成库。空 Upgrade 定义也可能是事件门控；周期事件和商店可能直接读持有量。物编沿有效 Upgrade 字段、数组索引、玩家与目标形态追到武器、能力、行为或效果。库注册后还要找事件启用者和具体地图入口。
3. **算最终收益。** 分清按总量设级、按本次新增量发放、处理函数内部自行按层循环，以及一次性或异步事件。混合实现各段分别记账，追到最终的资源、单位、属性或次数。若怀疑串读另一条天赋，固定自身层数只改变对照条目，再反向测试。
4. **对照恢复与说明。** 用相同持有量比较当场领取、跨图重建和同图重复初始化。依条目补测形态、死亡复活、作用玩家、目标过滤。核对实际发奖时机、难度系数、叠层方式及各语言玩家文本。依据实现与已确认设计分别判断该修文本还是修逻辑。

**单条交付**记录实例／升级 ID、获取入口、效果提供者、源位置、前置状态、操作、预期与观察、核清的范围和剩余缺口。复测一层、多层、恰好满层、余量不足和相关状态消费。静态解释器使用的引擎或 Bank 替身要写明。库存清点和根因确认分别计数。

**平衡请求**先排除错接线、漏发与重复发放。使用当前项目的难度、关卡时长、经济与奖励预算，按相同品质、用途、阶段和投入比较首层、追加一层、满层及触发频率。每个建议附对象 ID、当前有效值、建议值和能推翻建议的对照场景，具体数值写入项目档案。交付时标明哪些观察来自源码或替身测试，哪些已在编辑器或游戏中复现。

用[物编技能](../sc2-catalog-xml/SKILL.md)核对继承，用[触发器技能](../sc2-map-triggers/SKILL.md)查 GUI 调用，用[Bank 技能](../sc2-bank-system/SKILL.md)检查恢复顺序。
