# 地形模块制图对话示例

[English](terrain-conversations.en.md)

本页专用于 SC2 地形模块的制图请求。通用接入与模型调用见[技能对话](skill-conversations.md)，命令与事务规则见[地形指南](sc2-terrain-editing.md)。调用入口是 [sc2-terrain-editing](../../skills/sc2-terrain-editing/SKILL.md)；下列请求描述需求，不承诺每项已有自动写入实现。执行时查询 `capabilities` 和对应证据，不从历史案例推断当前地图已经通过验收。

## 开始一张图

可以先发送这一段，再选择下表中的具体制图请求。替换所有 `<...>`，矩形、点位和高度使用该地图核对后的坐标与单位：

```text
先读取 AGENTS.md、skills/sc2-project-entry/SKILL.md 和
skills/sc2-terrain-editing/SKILL.md。
源地图：<最新保存的Components地图路径>。
输出：<工作区内新的独立.SC2Map副本路径>。
目标：<战斗区域、路线、视觉主题和具体修改范围>。
保留：<剧情对象、原道路、区域、镜头、依赖与不可改变的地形>。
先查询当前制图能力，核对地图尺寸、坐标和实际依赖。
对已支持且在本次范围内的操作生成计划、复核差异并在副本执行；
不支持的部分明确指出，按单项编辑器实验补证据。
不要修改原图、publish或生成的Galaxy；静态、编辑器和游戏结果分别交付。
```

如果只有 `.SC2Map` 归档，先做格式识别；需要转 Components 时按[归档工具](../../tools/README.md)的显式转换流程处理。没有可用参考或真实 Components 基底时先说明缺失输入，不用空目录冒充完整地图。从零设计可以先产出布局草案；实际制图仍需有效基底或已支持的创建工具。

## 制图请求清单

| 编号 | 地形模块任务 | 可以直接发送的请求 | 关键边界与验收 |
|---|---|---|---|
| 01 | 只读查看当前地图 | “先只读检查 `<地图>`：总尺寸、可玩边界、地形主题、已有道路、水面、对象、区域和依赖。给我带坐标的诊断图与尚缺的证据，不修改。” | 地图参数决定目标，不默认改当前主模组；诊断图不是游戏渲染。 |
| 02 | 从参考图选基底 | “扫描 `<参考地图目录>`，按 `<城镇/荒野/虫族等需求>` 筛选少量候选。比较尺寸、可用地形与依赖，不复制项目机制，也不把社区改图称为官方原版。” | 区分 Components/归档与资源可用性；确定基底后再建立副本。 |
| 03 | 先画路线与空间 | “在 `<副本>` 规划入口、主路、交战区、支路和出口，坐标范围 `<范围>`。保留 `<原路线>`，预留 `<最大通行单位>` 和建筑入口空间；先给布局与待实现连接。” | 宽度是本图设计输入，不是通用寻路阈值；俯视连通仍需实机验证。 |
| 04 | 高度笔刷 | “对 `<区域>` 做 `<抬高/降低/平整/平滑/噪声>`，保护道路和周边层级。先确认支持的模式、通道与强度，用小范围候选展示前后差异。” | 细高度不等于悬崖层级；绝对高度或未支持模式先实验，保留模拟伴随数据。 |
| 05 | 地表纹理混合 | “将 `<区域>` 做成 `<道路/院落/岩土地边>`，查询本图已有纹理槽，沿用附近材质，做自然过渡并保留范围外纹理。不要铺成孤立矩形色块。” | 不凭纹理名称猜槽位；新建调色板与现有槽绘制是不同能力，需检查伴随数据。 |
| 06 | 悬崖与高低平台 | “在 `<位置>` 做 `<层级与边界>` 的高台/山壁。先查悬崖写入能力；无通用笔刷时保留原拓扑，准备单次升降层实验，不用高度鼓包替代。” | 普通悬崖升降、类型与同层操作各自取证，字节可读不等于拓扑正确。 |
| 07 | 坡道与连接方向 | “让 `<低地端>` 经 `<坡道宽度与方向>` 连到 `<高地端>`。先确认新增/删除/转向支持；缺少实现时在实验副本中做一个方向，保留旧坡道。” | 一方向/一套地形的成功不能证明任意坡道；保存重开后再测试步兵和车辆。 |
| 08 | 复用已支持的悬崖样本 | “若 `<参考图>` 的孤立单层岛能用于 `<目标位置>`，先核对版本、地形/悬崖调色板、平坦边界、范围与坡道相交情况，再生成受限印章候选。” | 仅适用当前 `cliff-stamp` 契约，不能据此承诺通用山体、坡道或任意层级移植。 |
| 09 | 水面范围与高度 | “调整 `<现有水面>` 的 `<矩形范围/局部高度/局部状态>`，以本图已有水状态为依据；保留其他水面，标明岸线与地形需要复核的位置。” | 查询局部状态及水类型，不把一个案例的高度/颜色验证扩展到全部水面行为。 |
| 10 | 道路 | “沿 `<两端坐标>` 铺直路，复用本图 `<已有原生直路组>` 的材质和宽度。保持旧道路与地面连贯；如要曲线或改宽度而工具不支持，单列编辑器步骤。” | 当前直路模板、移动/复制与任意曲线不同；道路视觉不建立真实可通行性。 |
| 11 | 植被 | “在 `<区域>` 稀疏/补充植被，使用本图已确认可见的模板和 `<随机种子/密度>`，清空道路与建筑入口附近的小范围，保留其他实例。” | 现有实例散布/删除与原生允许、禁止、密度、重生成笔刷不同；未知标记不能保证显示草。 |
| 12 | 光照区域 | “在 `<区域>` 加强/移除 `<已有光照区域>`，按现有 LightingMap 与允许通道生成候选，保留其他区域。给出游戏视角的观察要求。” | 现有区域绘制不等于创建任意灯光定义；视觉效果需要实际 Editor/渲染观察。 |
| 13 | 预放菌毯 | “在 `<范围>` 绘制/清除预放菌毯，保护范围外数据。先查本图是否符合整格、比例与偏移限制；游戏中菌毯来源另行验证。” | 预放菌毯层、允许掩码与运行时蔓延不是同一机制。 |
| 14 | 视野阻挡 | “在 `<整格范围>` 绘制/移除视野阻挡，保留通道与其他区域。说明它和地面阻挡、战争迷雾、单位视距的区别。” | 视野层操作不能替代地面寻路或全局迷雾设置；实际单位视线需场景测试。 |
| 15 | 单位摆放与阵形 | “在 `<区域>` 复用已确认可用的 `<单位类型/模板>`，按 `<阵形与间距>` 放置；守卫朝 `<入口>`，避开已有单位和路口，不改变任务脚本。” | 核对活动依赖与模板；摆单位不等于启动 AI、援救或任务目标。 |
| 16 | 装饰物与落地 | “沿 `<街边/山壁>` 放置 `<建筑/岩石/设施>`，按布局旋转、缩放并贴地。高架与桥面物件保留设计 Z；先查模型朝向和高度模式，避免埋地。” | 原地朝向与绕轴旋转位置分开；地形采样不能识别任意桥面或平台。 |
| 17 | 点与区域 | “在 `<副本>` 放置/调整 `<点位或矩形/圆形区域>`，保留已有 ID 和类型引用。删除前检查触发器引用；新增任务事件另交地图触发器技能。” | 有引用对象不能直接删除；创建出生点或任意重映射引用需专门支持。 |
| 18 | 镜头与画面检查 | “核对 `<已有镜头>` 和 `<预期游戏视角>` 下的布局，比较主体遮挡、街道边界与入口。需要新镜头或属性写入时先查当前实现，再安排编辑器操作。” | 相机坐标/对象诊断不代表已实现相机编辑或原生渲染。 |
| 19 | 地面寻路涂层 | “对 `<整格范围>` 绘制/清除补充地面阻挡，先核对原有 Pnp 与工具拥有的装饰物阻挡记录；保留其他原生与细格数据。” | 清除补充涂层不会强制打通悬崖或原生足迹；空军、建筑放置与实机寻路分别验证。 |
| 20 | 建筑围合与静态阻挡 | “为 `<静态建筑/山石集合>` 根据实际足迹或已测形状补阻挡，预留 `<通道矩形>`。移动或删改后同步其拥有的贡献；可破坏/可移动物件保留原生行为。” | 不从模型大小推断足迹；一次同步包含全部管理对象，保留原始与重叠涂层，通道冲突停止规划。 |
| 21 | 可玩边界 | “在当前总尺寸内调整可玩边界为 `<矩形>`，核对旧对象、区域和镜头关系，保留边界外原始组件，说明镜头边界是否另需操作。” | 修改 MapInfo 可玩范围不等于扩尺寸，也不自动改变相机边界。 |
| 22 | 扩尺寸与坐标原点 | “现有画布确实不够，需向 `<方向>` 扩展到 `<目标尺寸>`。先核对总尺寸、原点、旧路线与所有引用；通用扩尺寸写入不支持时，给出独立 Editor 实验方案。” | 不只改头部尺寸或复制项目专用单元转移代码；保存、重开和全部受影响通道需要证据。 |
| 23 | 桥梁与隧道地形 | “让 `<桥/隧道>` 与 `<两端道路>` 连通，核对原生模型、朝向、足迹、地面高度和车辆净空。桥面保留设计高度，山壁约束不改成额外绕路。” | 完整模型替换也不证明可跨越；步兵和目标车辆分别测试，传送不是地形修复。 |
| 24 | 场景细化 | “`<场景>` 显得空。先在游戏视角检查轮廓、街边和院落围合，补主体建筑、岩体和设施，再加少量地面细节；保持战斗与车辆空间。” | 不以碎物数量或俯视点图验收美术；大模型占地和遮挡仍需观察。 |
| 25 | 计划、撤销与恢复 | “对 `<工具工作副本>` 预览这组修改，复核组件差异后按已授权范围应用。若要撤销/重做，先确认地图与相邻历史指纹匹配；不要覆盖后续人工修改。” | 工作副本与历史共同保留；源/历史变更就停止旧方案，保留失败日志与备份。 |
| 26 | 编辑器保存与续作 | “对 `<本次副本与操作>` 保存、关闭、重开并复核。可用的授权 GUI 步骤由你执行，其他必要步骤交给我。先捕获原始保存差异，再审计明确地图/locale 的字符串锚点。” | 保存会归一化组件并使旧历史失效；基于最新保存版建立新副本，按操作分别记录验收。 |

## 多轮制图对话

### 从灰盒到可检查的地形

**用户：** “用 `<参考Components地图>` 做一张小型城郊战场，输出 `<新副本>`。入口在南，出口在北，中间是院落；先保留现有坡道和道路，不接任务逻辑。”

**智能体：** 查询能力、尺寸、坐标与依赖，确认路线和空间需求。在副本上按已有模板安排布局；区分地形修改、对象摆放与任务触发器，交付计划、差异、审计和待验项。

**用户：** “北边做一层高地，入口坡道朝南。院落的地表太方，改成铺装到岩土的过渡。”

**智能体：** 将纹理混合与悬崖/坡道分开处理：已有纹理槽按支持范围制作候选；若层级和方向缺少通用写入实现，保留原拓扑并准备单项编辑器实验。不会用平滑隆起来代替一层高地。

**用户：** “编辑器保存重开后纹理没问题，高地是我手工做的，坡道还没测。”

**智能体：** 先记录原始保存差异。纹理只获得本次范围的 `Editor accepted`；手工高地记为人工实验，不能认定自动写入器通过。坡道保留待验；下一轮从最新保存版开始，再测试所需单位通行。

### 摆景、阻挡与道路联动

**用户：** “在 `<当前工作副本>` 街道两侧放建筑和岩石，留出 `<车辆类型>` 的通道；单位朝入口，别埋进地里。”

**智能体：** 核对已放对象、依赖、朝向与高度模式，先布大体量围合再加细节。用实际足迹/已测形状建立静态阻挡，保留道路与设备入口；可破坏道具使用原生行为。

**用户：** “把东边三栋楼向外移，入口放宽，删掉那辆会被任务摧毁的车。”

**智能体：** 复核对象引用；有引用的车停止直接删除并路由到 GUI 修改。楼体移动同步其工具拥有的阻挡贡献，保留其他涂层；变更在同一副本事务内审计，不留下旧位置的永久阻挡。

**用户：** “保存重开后没有报错，接下来怎么验证？”

**智能体：** 先确认实际保存产物和检查范围，再分别验证游戏视角下的落地/遮挡、步兵与车辆走完整路线、车辆被任务销毁后是否解除阻挡。编译无错误不等于这三项通过。

## 交付与资料选择

制图结果应包含明确的输入/输出、修改范围、实际组件差异和未完成项。`static validation passed`、`Editor accepted`、`packaged runtime passed` 只用于相应证据；不要把工具能运行、组件能解析或一次人工操作，写成整个地形模块已经实现。

具体操作 JSON、格式、案例和实验步骤分别按[地形技能](../../skills/sc2-terrain-editing/SKILL.md)中的指针加载。此页提供对话，不复制操作参数契约；地形工具更新后，以当前 `--help`、源码和能力清单重新判断。
