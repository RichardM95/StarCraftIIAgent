# 技能调用与对话示例

[English](skill-conversations.en.md)

在克隆的工作区中开始对话，让智能体先读取 [AGENTS.md](../../AGENTS.md) 和[项目入口技能](../../skills/sc2-project-entry/SKILL.md)。工作区包含 **34 个技能：15 个根技能、13 个 Galaxy 子技能、6 个 SC2Data 子技能**。完整根路由见 [README](../../README.md#任务路由)，Galaxy 与 SC2Data 由各自根技能继续路由。

## 如何调用

具体地形模块制图另有[26 个专项场景和两组多轮对话](terrain-conversations.md)，包括高度、纹理、悬崖/坡道、水体、物件、寻路与保存后的续作。本页保留跨技能接入和协作示例。

通常直接描述目标即可；需要固定入口时，写明“读取 `skills/<技能ID>/SKILL.md` 并按其流程执行”。工作区技能文件不一定出现在宿主的全局技能菜单中，明确读取路径同样有效。若宿主已经发现该技能，也可以使用它提供的技能选择器；不要假定输入 `$技能名` 就完成安装。

示例中的 `<...>` 都要换成实际输入。地图任务以明确指定的地图为目标；初始化模组、临时检查地图、模型分包和全局注册是不同操作。UI 语言与 SC2 数据 locale 分开指定。不要把凭据写进对话、任务包或 Git。

## 可复制的请求

| 编号 | 场景与技能 | 发给智能体的请求 | 应交付的结果 |
|---|---|---|---|
| 01 | 新机器首次检查：`sc2-project-entry`、`sc2-tools-validation` | “这是刚克隆的工作区。检查规则、技能与工具是否完整，运行 tools、docs 范围检查。不选择项目，不复用其他机器的配置。” | 检查结果、缺失依赖；未初始化项目应明确报告。 |
| 02 | 明确加载技能 | “先读取 AGENTS.md、skills/sc2-project-entry/SKILL.md，再读取 skills/sc2-terrain-editing/SKILL.md。目标是 `<地图.SC2Map>`，本轮只读。” | 确认实际地图、能力与调查范围，不因当前主模组改变地图目标。 |
| 03 | 地形只读调查：`sc2-terrain-editing` | “检查 `<地图.SC2Map>` 的格式、尺寸、可玩边界、已有对象与地形能力。先查询 capabilities，做有范围的审计与预览，不写入。” | Components/归档区别、现有证据、未实现项；预览不是游戏渲染或原生寻路。 |
| 04 | 扩建与场景布置：`sc2-terrain-editing` | “以 `<最新保存的地图>` 为基底，在 `<工作区新副本>` 扩展 `<方向与功能空间>`。先读 map-adaptation 资料，保留剧情对象、旧路和坐标约束。先布局连通空间，再布置建筑与环境。” | 明确输入/输出、哈希绑定方案、差异与独立副本；未验证的连接继续列为待验。 |
| 05 | 朝向、落地与阻挡：`sc2-terrain-editing` | “调整 `<对象集合>` 的位置和朝向。普通对象贴地，桥面物件保留已设计高度；核对已有占地和保留通道，只依据实际证据补静态阻挡。” | 位置、朝向、高度模式与阻挡归属的差异；不凭包围圆推断原生碰撞。 |
| 06 | 桥梁或隧道：`sc2-terrain-editing`、`sc2-catalog-xml` | “调查 `<桥/隧道对象>` 为什么看似连通却可能不可走。核对活动依赖、模型、足迹、两端地面和要求通行的车辆，准备独立修复候选。” | 数据与地形证据、候选和步兵/车辆测试步骤；静态图不证明通行。 |
| 07 | 补编辑器证据：`sc2-terrain-editing`、`sc2-editor-handoff` | “在独立副本上验证 `<单项操作>`。若已授权的 GUI 控制可用，由你完成保存、关闭、重开并记录；否则只列出我必须操作的步骤。先保存原始差异，再处理字符串锚点。” | 绑定具体操作与产物的证据；不把一次保存扩大成全部地形能力通过。 |
| 08 | 任务对象与 GUI 组织：`sc2-map-triggers` | “在 `<地图.SC2Map>` 给 `<任务对象>` 接入可编辑 GUI 目标和交互，并整理触发器目录。保留对象引用、既有初始化与行为；不要修改生成 Galaxy。” | GUI 引用检查、实际结构差异与编辑器交接；项目案例脚本不能直接套用到其他地图。 |
| 09 | 选择性迁移：`sc2-unit-migration` | “从 `<来源模组列表>` 迁移 `<单位ID列表>` 到 `<目标模组>`。先分析各来源完整官方基线、重名来源、数据链和外部机制；本轮只生成选择与方案，不应用。” | 来源选择、ID 映射、资源与机制缺口；来源不完整或动态引用未解决时停止可执行导出。 |
| 10 | 明确复制本地覆盖：`sc2-unit-migration` | “我明确需要包含官方同 ID 本地覆盖的原始层合并。来源优先级为 `<低到高>`，目标依赖固定。先展示整条目冲突、保留的官方引用和备份方案。” | 区分原始层合并与完整可玩单位迁移；实际写入前复核目标与方案。 |
| 11 | 官方资源：`sc2-official-assets`、`sc2-actor-system` | “为 `<对象ID>` 查询 `<主题/皮肤>` 的官方模型、肖像与音效链。先判断是同一单位外观替换还是新增并存单位，再核对活动依赖和实际资源。” | 有范围的索引结果、Actor/素材链与读取状态；索引命中不等于编辑器外观通过。 |
| 12 | MCP 与本地入口：`sc2-shared-tools` | “调查 `<明确目标>` 的 `<资源引用/地图外壳/地区环境/编辑器警告>`。查询当前工具 schema，优先已连接 MCP，未连接时使用同一实现的本地命令。” | 入口、目标与业务诊断；已有 Catalog、GUI、地形和本地化流程继续用原工具。 |
| 13 | 事务不确定：`sc2-shared-tools` | “应用 `<候选ID>` 时连接断开了。先查询原事务状态和源指纹，不重复提交，不换 CLI 绕过业务拒绝；按已确认状态继续或恢复。” | 明确任务/事务状态、冲突与恢复条件；没有状态证据不重复写入。 |
| 14 | 指定模型分包：`sc2-deepseek-tasks` | “列出本机 Harness 可用 provider/model ID，使用 `<provider>/<model>` 检查 `<独立SC2子任务>`。仅允许 `<文件清单>`，先写清目标、限制和验收，再在隔离副本执行。” | 受限任务包、共享任务ID、实际候选差异和主智能体独立验收；不展示密钥。 |
| 15 | 重连与取消：`sc2-deepseek-tasks` | “恢复查询 `<任务ID>`，不要另派同一任务；若仍在运行则取消，说明哪些候选尚未整合。” | 原任务状态与取消结果；worker 完成不自动成为 Editor 或游戏验收。 |
| 16 | 优化技能：`sc2-tools-validation` 与 Harness2 | “用现有 Harness2 优化 `<已登记技能ID>`。固定模型和源指纹，先基线，再一轮 parallel 与独立案例。主智能体复核完整差异；无可靠收益就保留原样。” | 训练/独立案例、知识迁移和实际输入 token；分组采用路由纠正或含资料读取的平均输入至少减少 10% 门槛。 |
| 17 | 新机器启用共享工具：`sc2-shared-tools` | “按 shared-tools 指南检查 Python 3.12 与本机 Harness，安装独立环境，使用我本机保存的 provider 配置，诊断后注册全局入口。保留其他 MCP 服务和 Hub 归属。” | 本机安装与配置、备份及诊断；客户端实际连接后才报告 MCP 可用。 |
| 18 | Git 分发：`sc2-tools-validation` | “检查通用工具、技能和使用说明能否独立分发。排除 projects、本机配置、环境、凭据、报告和运行状态，再执行 tools/docs 检查。” | 分发检查结果；项目地图和历史产物不进入套件 Git。 |

## 多轮协作

### 地图扩建与验收

**用户：** “在 `<地图>` 北侧增加设备院落，输出到 `<新副本>`，保留旧路和任务引用。”

**智能体：** 核对最新保存源、能力和引用，提出连通空间与场景方案，执行已授权的独立副本修改，给出实际差异和静态检查；将模型遮挡、坡道或桥梁通行列为独立验收项。

**用户：** “院落看起来仍然空，先增加建筑围合，入口保留车辆空间。”

**智能体：** 在当前副本上复核大体量建筑、轮廓与通道，使用有证据的占地和高度模式。只有取得实际渲染/编辑器观察后才判断外观；不以摆件总数或俯视点图证明美术质量。

**用户：** “编辑器保存重开后目录和编译通过，但桥还没测。”

**智能体：** 记录目录持久化与编译的 `Editor accepted`，保留桥梁、车辆和其他运行场景待验。下一次外部修改前确保地图已关闭，以最新保存版本重新绑定方案。

### 模型分包与整合

**用户：** “使用 `<provider>/<model>` 修复 `<已授权SC2任务>` 的一个独立子问题。”

**智能体：** 确认范围、允许文件、现有依据和验收，在隔离副本提交一次，记录 request_id 与 task_id。

**用户：** “界面断开了，现在继续。”

**智能体：** 查询原任务，不重复派发。取得候选后检查真实差异、源指纹、桥接事件及越界标记，运行独立验证，按同一事务流程整合达标内容。

**用户：** “worker 说已经修好，可以写游戏验收通过吗？”

**智能体：** 只报告实际证据对应的状态；静态检查最高为 `static validation passed`。编辑器保存/重开与游戏场景各自验证，不能由模型文字代替。

## 命令与恢复

从工作区根目录运行，命令参数以工具 `--help` 为准：

```powershell
python tools/test-suite.py --ui-language zh-CN --scope docs
python tools/test-suite.py --ui-language zh-CN --scope tools
python tools/sc2-terrain.py --ui-language zh-CN capabilities
python tools/sc2-migrate.py --ui-language zh-CN --help
python tools/sc2-local.py --ui-language zh-CN tools
python tools/deepseek-task.py --ui-language zh-CN models
python tools/harness2.py --ui-language zh-CN sc2-optimize --skill galaxy-language-fundamentals
```

前两个检查不需要活动项目。共享 CLI 需要[本机独立环境](shared-tools.md)，模型分包还需要本机 Harness/provider；Harness2 优化需要[Linux/WSL 环境、Codex 登录与模型连接](harness2.md)，会消耗模型额度。自然语言示例不是自动确认部署、全局注册或任意外部写入的通行证；以当前用户授权的实际目标和范围执行。恢复使用对应任务/事务/实验的状态和指纹，不覆盖后续用户修改。
