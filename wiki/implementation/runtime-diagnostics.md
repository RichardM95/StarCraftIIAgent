# 运行时排错与机制边界

适用于卡顿、闪退、UI 异常、技能状态与关卡事件排错。来源编号见[伊罕利开发经验](../../docs/agents/retrospective.md)；这些是调查方法和局部案例，不是所有 SC2 版本的引擎定律。状态门槛见[反馈流程](testing-feedback-workflow.md)。

## 先证明运行的是本次修改

核对目标组件、活动依赖、编辑模式及本次生成代码中的关键动作。XML 有节点不代表动作有实现，也不代表编辑器已生成它；计时器清理要读实际调用及执行路径。生成的 Galaxy 只读，重生成按[编辑器交接](../guides/editor-handoff.md)执行。

测试记录区分全新开局、普通读档、胜利转场、跨关卡和重复施放。旧存档可能保留变量、单位及已创建行为；旧存档结果不能单独证明新初始化失败。用户已确认的当前测试条件在同一轮复用。

## 卡顿与闪退

先按发生阶段拆分：加载末尾、开局初始化、进入瞄准、施放中、结束后仍累积、特定单位死亡或过场结束。记录地图、单位规模、同场操作及日志时间。

- 镜头移向空地后的变化可帮助区分画面负载与持续模拟负载，不能直接证明瓶颈。
- 对重复施放，在施放前、清理等待后记录计时器、临时单位、活动效果或搜索次数是否回到基线。源码中“创建多”不是泄漏证据。（S1）
- 性能候选每次只改变一个因素，对照相同存档/新开局、镜头和操作。降低搜索频率可能改变移动目标命中及总伤害；用户要求保留伤害时，先考虑专用视觉链。（S1、S2、S4）
- 闪退优先核对同次崩溃调用栈与日志；常驻警告或独立脚本错误不自动成为根因。停用可疑 UI 后仍崩溃，应回到剩余调用链。（S7）
- 周期扫描先确认战役 AI 等子系统已启动；无单位事件上下文的定时扫描，应使用当前迭代单位，不读取 EventUnit。确切 API 从目标定义查询。（S7）

## UI、Actor 与资源

按功能和表现分别取证：按钮不可见时测试快捷键；能量数字、数值绑定、水位动画和技能可用性分别检查。先读布局边界、锚点和实际动画名称，再决定是否增加显隐动作或刷新循环。（S1、S5）

同名模型或 DDS 的最终提供者由活动依赖和覆盖顺序确定。黑块、异常高亮或重复特效时，先核对 Graphics 日志、模型材质/发光贴图、继承事件及多名单位叠加；Actor 透明度不保证控制所有发光层。DDS 可解码不等于游戏可正确加载。针对官方路径覆盖的隔离测试应保留备份，避免先改地形。（S2、S3、S6）

仅缩减表现时使用专用 Actor/模型覆盖，保留弹道、范围提示、单位数量和战斗结算。只有同场复测才能声称观感或帧率改善。

## 技能与事件状态

- 重复创建/进区域事件可能再次命中同一单位。授予唯一强化前检查本单位已有行为；死亡、行为丢失和所有者变更后回收名额。玩家拥有某精英不能代替当前选中单位持有对应行为。（S2）
- 自动施法核对能力入口是单位、地点还是二者；区分选点前验证、自动索敌和结算验证。局部测试应覆盖手动/自动、普通/变身、近距/远距。（S6）
- 冷却、临时护盾、形态回退等机制列出部署、正常施放、进化、重生、取消与异常退出路径。初始化只处理初次状态；普通施放避免再次叠加原生冷却。清理与奖励只结算一次。（S6）
- 吸血、分担与普攻计数要明确每次攻击、每段伤害、主/副目标和技能伤害的边界；排除递归及非战斗的到期/自毁伤害。测试护盾吸收、无效命中、目标死亡和临时单位清理。（S2、S6）

## 关卡目标与持久化

目标创建与完成应能应对“先救援、后发现”等顺序；重复事件不重复奖励。排队对白执行前重新核对目标状态，避免完成后又建立进行中目标。（S3）

生存奖励跟踪指定初始单位，不因补兵或复活恢复资格；在结尾动画前冻结结果，最终胜利时提交，并保留过去已解锁奖励。具体存储键与提交位置取当前项目证据。（S3）

任务文案、计数器和胜利判定读取同一门槛；先区分当前资源与累计采集、初始储量与容量。资源建筑替换还须检查底层资源与建筑的关联，不能只改上限就宣称归零已解决。（S2、S3）

Bank 丢失先按[Bank 系统](bank-system.md)核对磁盘、内存状态及转场目标地图的加载/应用链。
