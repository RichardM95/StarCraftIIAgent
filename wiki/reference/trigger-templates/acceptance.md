# GUI 模板实际验收记录

本页提供七类模板的后续验收格式。当前均为 `static validation passed`；编辑器与游戏证据尚未取得。模板目录是片段集合，实际验收需独立测试地图，不将它当作完整地图打开。测试项目的记录保存到该项目资料目录，不选择或修改当前工作区项目。

移植前核对 [清单](manifest.json) 和实际文件指纹。原模板、移植后的源、编辑器保存后的源分别保留指纹；模板或原生源变化后重新静态检查。重新分配本地 ID、同步字符串，确认目标基础库来源，再按 [模板说明](README.md) 替换输入。

## 七类验收场景

| 机制 | 必填替换输入 | 编辑器检查 | 游戏操作与预期 |
|---|---|---|---|
| initialization | 初始化入口、消息 | 事件引用保留，生成 Map Initialization 注册 | 启动地图；消息只显示一次 |
| objectives | 文字、目标句柄、完成条件 | 创建后立即保存正确句柄，完成 worker 引用同一变量 | 创建两个目标；完成指定目标，另一个保持活动 |
| victory-defeat | 玩家、胜败条件、进度流程 | 两个 worker 的玩家和结果预设正确 | 分别运行胜利与失败场景；结果正确，项目进度按约定保存 |
| regions | 实际区域、玩家及单位过滤 | 区域引用和过滤条件保留 | 符合条件单位进入时触发；离开或其他单位进入时不触发 |
| timers | 时间、重复选项、启动调用 | 到期事件和启动动作使用同一 timer | 启动前不触发；到期触发，重复行为符合配置 |
| waves | AI 玩家、启动流程、非空单位组、目标点 | AI 入口、单位组及目标点正确 | 调用后单位进攻目标；再次调用无脚本错误或意外重复任务 |
| difficulty | 玩家、两个难度值、分支动作 | 难度预设与 if/then/else 归属正确 | 分别以两个难度启动；进入对应分支 |

编辑器保存成功还需核对 GUI 结构与生成调用，不仅记录“打开没有报错”。普通编辑器测试运行不能替代打包运行证据。生成的 Galaxy 只读对照，修改仍回到可编辑源。

事件排列与模组链接器的待验证规则另做两组最小对照：相邻/远置事件声明、GUI action/等价 Custom Script 调用。记录相同依赖与版本下保存前后的差异，检查实际事件注册和库调用，再记录游戏结果。单个版本的结论注明适用范围。
