# 用户与智能体的触发器对话示例

本页示范如何提出需求，以及智能体应采取的动作和交付内容。它不是已执行项目的记录，也不新增验收证据。路径、角色、单位、区域、文字与进度入口均需替换成真实输入；函数和参数 ID 来自当前目标查询。执行规则以 [知识入口](trigger-knowledge.md) 为准，游戏内对白案例见 [游戏对话机制](trigger-dialogue-examples.md)。

答复应反映实际工作：能从配置或源文件查到的信息直接查；缺失且会影响实现的信息再询问；已有授权内的编辑和检查直接完成。完成后说明行为、证据与尚待实际验收的部分。下面的“答复要点”不是要求机械复述的固定话术。

## 目标、依赖与参考调查

| 场景 | 用户说法 | 智能体应执行 / 答复要点 |
|---|---|---|
| 01 未选择项目，只研究 | “先看看官方怎么实现多句对白，不改任何地图。” | 显式参考查询并核查案例。交付来源、调用关系和资源需求；状态为 reference_only，不初始化项目 |
| 02 显式地图修改 | “在 `<地图.SC2Map>` 中增加进入基地后的对白，Mods/Campaigns 在这两个目录。” | 用显式目标解析依赖；检查区域与对白资源，再编辑实际 Triggers。缺少必要对象时指出具体输入 |
| 03 已配置项目 | “给当前模组加一个显示任务提示的 GUI action。” | 从 source_mode 定位编辑源，确认库身份和加载范围；创建导出的 GUI action，并说明地图调用入口 |
| 04 用户要求初始化 | “选择这个主 Components 模组：`<主模组.SC2Mod>`。” | 直接调用初始化工具，检查项目身份与编辑源；随后继续已授权工作，不让用户手改配置 |
| 05 只有 Liberty | “地图只有自由之翼依赖，借用这个 Lotv 函数。” | 查询实际根定义与间接依赖。未加载则拒绝该引用，寻找目标可用的实现；保留不兼容原因，不擅自添加依赖 |
| 06 同意调整依赖 | “我已在编辑器添加所需组件，重新检查。” | 读取新的真实依赖声明，检查库登记与文件指纹；链完整后再确认，不沿用旧可用性结果 |
| 07 只有库文件 | “磁盘上有 VoidLib，为什么不能使用？” | 展示组件加载证据和库登记证据的差别；列出缺失声明或未解析引用，可继续参考研究 |
| 08 网络依赖缺失 | “这个 Battle.net 依赖能先忽略吗？” | 报告具体网络引用与受影响调用链。允许显式参考调查，目标检查仍失败；不把忽略后结果称为确认可用 |
| 09 模组与地图作用域 | “地图里这个本地函数，模组能直接调用吗？” | 分别检查目标作用域。地图本地定义不能成为模组可用定义；若需要共享，实现模组 GUI action 并由地图调用 |
| 10 参考与活动来源冲突 | “同一个 Library/Id 查到了两个不同版本，选哪个？” | 比较目标实际加载来源与指纹，报告冲突；参考同 ID 不替代活动来源，实际歧义解决前不通过检查 |

## 完整定义与官方案例查询

| 场景 | 用户说法 | 智能体应执行 / 答复要点 |
|---|---|---|
| 11 中文名称查询 | “查一下‘发送传输’的完整参数。” | 在目标可用集合按中文、英文和内部名检索；存在多个候选时根据意图与签名区分，交付精确引用与原 XML |
| 12 精确元素查询 | “解释 `Ntve:FunctionDef:3E151A17`，包括默认值和返回值。” | 查询完整定义，分别列出参数 ID、类型、顺序、默认结构、预设及相关标记；核对目标可用性，不凭记忆补签名 |
| 13 默认值误解 | “既然有默认值，我可以省掉这些 Param 吗？” | 核查当前定义与调用要求。默认结构作为定义事实保存；GUI 调用仍显式绑定必要参数，不把默认值自动解释为省略许可 |
| 14 跨库参数 | “动作能找到，但 ParamDef 报不存在。” | 沿参数所属 Library/Type/Id 检查，定位具体缺失库或错误归属；不把参数 Library 改成动作 Library 来消除报错 |
| 15 子动作错误 | “If 的 Then 分支保存后消失了。” | 查父定义允许的 SubFunctionType 和孩子引用，修正 GUI 结构；保存行为需实际 Editor 对照，静态通过不声称已解决保存问题 |
| 16 从 Void 地图取原生案例 | “这个 Void 地图的计时器能移到 Liberty 地图吗？” | 比较案例实际引用闭包与目标库；仅按来源地图年代排除不合理。地图对象、文字、变量和本地 ID 另外迁移 |
| 17 原例过大 | “我只想学按钮事件，不要整套剧情 UI。” | 选择小范围 dialog-button-response / dialog-add-button，核查控件事件和句柄；说明调试行为要替换，避免导入整个故事流程 |
| 18 列出全面案例 | “把对白、对话框、镜头和跳过的例子都列出来。” | 分四类给摘要与 case_id，保留依赖和资源需求；按需展开精确调用，区分精选原例与尚无验证证据的扩展 |

## 七类基础触发器开发

| 场景 | 用户说法 | 智能体应执行 / 答复要点 |
|---|---|---|
| 19 初始化 | “地图开始时执行一次模组初始化。” | 检查既有初始化、导出的 GUI action 和实际调用顺序，防止重复入口；Bank 名称与项目身份由源确认 |
| 20 目标 | “摧毁三个建筑后完成指定任务目标。” | 查对象与创建/完成动作，创建后立即保存目标句柄；实现计数与条件，避免完成另一个 LastCreated 目标 |
| 21 胜败 | “基地被毁就失败，消灭敌人就胜利。” | 查单位与玩家、既有结算/进度保存入口，接入 GUI 条件；分别检查胜败，不用普通结束游戏替代项目进度流程 |
| 22 区域 | “只有玩家 1 的英雄进入区域才触发。” | 解析实际区域、英雄与玩家过滤，明确一次/重复触发；区域缺失时要求编辑器建立对象，不猜地图对象 ID |
| 23 计时器 | “两分钟后开始任务，并显示倒计时。” | 创建并保存 timer，用同一对象启动、显示及注册到期事件；核对计时模式与重复策略，窗口与 timer 分别管理 |
| 24 波次 | “每三分钟向基地派兵，难度越高兵越多。” | 检查 AI 启动、单位组、目标点和波次调度；查询目标的难度与波次定义，优先可编辑 GUI；生成 Galaxy 只读 |
| 25 难度分支 | “普通给 5 个单位，困难给 8 个。” | 查询实际难度预设及 ValueId，检查分支条件和参数；不把示例数字 3 永久当成某个难度名称 |

## 游戏对白与交互开发

| 场景 | 用户说法 | 智能体应执行 / 答复要点 |
|---|---|---|
| 26 单句带语音对白 | “触发时播放角色语音，带头像和字幕。” | 确认收件玩家、声音、头像及字幕资源，查目标发送定义；需要战役封装时检查 Camp/Lbty 等实际依赖 |
| 27 三句顺序对白 | “A、B、A 依次说话，别同时播放。” | 核查 sequential-lines 与等待定义，立即保存每次发送的句柄；安排队列和打断规则，避免 LastSent 被其他对白覆盖 |
| 28 无配音对白 | “暂时没有音频，先实现文字与头像。” | 查询目标能表达的文字/头像路径，明确显示时长与关闭行为；不伪造不存在的声音资源，也不把静态检查当成画面验收 |
| 29 Conversation data | “使用已有 Conversation，角色和镜头都在地图里。” | 查 Catalog 条目及角色/camera 绑定，登记实际对象后运行；如果缺资料，指出具体数据或对象，不只复制 Run 动作 |
| 30 两个剧情选项 | “弹出两个按钮，选择之后进入不同目标。” | 创建并保存 dialog/按钮句柄，事件按按钮和玩家分支，防重复提交，清理窗口；目标句柄与玩家选择状态分别保存 |
| 31 超时默认选择 | “十秒没选就默认选第一个。” | 设计点击与 timer 共用的选择提交入口，先检查未提交状态，再执行一次分支与清理；原例尚未验证该组合，需新实现与验收 |
| 32 一次性与冷却对白 | “这个提示只说一次，另一个最多每 30 秒说一次。” | 在实际事件与动作前检查状态/冷却，先更新状态再入队；核对清理、重新开始和读档后策略 |
| 33 随任务进度变化 | “任务完成前后点击角色，要说不同台词。” | 读取已确认的任务状态入口，条件选择对应资源；若项目未约定状态，提出具体状态方案后确认实质选择 |
| 34 可跳过剧情 | “按 ESC 跳过对白，然后继续任务。” | 查询实际按键/跳过定义，正常结束和跳过共用清理；停止正确的 worker，恢复镜头、控制和 UI，并避免重复推进任务 |
| 35 多人独立选择 | “合作模式每个玩家分别选奖励。” | 先区分独立 UI、个人结果与共享任务状态，确认可用玩家/控件事件定义；以玩家存储选择并安排同步测试，单人官方原例不能证明多人正确 |
| 36 窗口重开与布局 | “关掉后还能重开，长文字不要溢出。” | 明确隐藏/销毁策略、句柄复用、布局与文字范围；检查实际字体、分辨率和输入设备，静态只检查结构与引用 |

## 排错、迁移与交接

| 场景 | 用户说法 | 智能体应执行 / 答复要点 |
|---|---|---|
| 37 迁移 ID 冲突 | “把这个 GUI 片段放入现有地图。” | 先确定本地闭包，重新分配声明/引用 ID，同步 TriggerStrings 与 GameStrings；模组 Library 归属另行设置 |
| 38 参考索引过期 | “换了官方库后，查询结果还是旧的。” | 核对输入清单和指纹；旧版/过期索引从原外部根重建，再核对案例来源指纹，变更案例需重新核查标签 |
| 39 引用截断误解 | “只显示 50 个节点，是不是只检查了 50 个？” | 说明展示截断与完整检查区别，报告总数及隐藏部分错误；不能把有限输出当成完整可用性证据 |
| 40 Editor 保存后变化 | “静态通过了，但编辑器保存后动作不见了。” | 保留保存前后源和生成代码，对照精确调用与参数；记录 Editor 版本、复现步骤，实际确认前不宣称 Editor accepted |
| 41 游戏中卡住 | “对白播完之后，镜头和控制没有恢复。” | 查看正常/跳过/打断路径、暂停和 UI 状态、等待上下文及日志；修复可编辑源，再给出对应复现步骤 |
| 42 请求跳过依赖检查 | “直接检查主模组，别管依赖。” | 解释 catalog 可裁剪调查范围，但触发器可用性仍需完整活动依赖；给出具体缺口，依赖不足不能通过验收 |
| 43 用户报告编辑器通过 | “我已重载保存，这是前后文件和版本。” | 校对对象、GUI 和生成调用是否保留，再登记 Editor accepted；没有游戏证据仍待运行验收 |
| 44 用户报告打包通过 | “打包后正常、跳过和重复触发都跑过，这是日志与录像。” | 核对版本、打包方式与场景覆盖，逐项记录实际结果；只有证据支持的场景登记 packaged runtime passed |

## 两段完整对话写法

### 缺少目标时先研究

**用户：**“给我一个有头像、三句对白、最后两个选项的例子，先不要改地图。”

**智能体：**“我会分别查询顺序 Transmission 和 Dialog 按钮事件，整理组合写法及所需输入。当前没有目标，这些结果只作为参考。”

**用户：**“只用普通原生库，别依赖战役包装。”

**智能体应执行：**查询 Ntve 的发送、等待、窗口和控件定义；原例中 Camp/Lbty 调用明确排除。提供 GUI 编排、玩家/声音/文字/头像/句柄输入，以及实际目标的后续检查步骤。没有生成并检查 XML 时，标为设计写法，不能称作静态通过的模板。

**完成后的答复要点：**“已整理普通原生写法，官方顺序对白仅作机制参考。目标加载、资源替换与 XML 检查仍需实际地图证据。”附实际查询来源。

### 有目标时完成工作再交接

**用户：**“在 `<目标.SC2Map>` 添加玩家 1 进入 `<区域>` 后的一次性对白。声音、字幕、头像在这些资源中；只允许已加载库。”

**智能体应执行：**解析目标与依赖，核查区域与资源，查询完整定义，编写 GUI 和文字锚点，更新一次性状态，再运行目标检查。所有输入完整时直接完成这些已授权动作。

**完成后的答复模板：**“已加入进入区域后的单次对白。核对了收件玩家、状态变量和资源引用；目标检查结果为 `<实际状态>`。请按附带步骤验证声音/头像/字幕及重复进入行为。”

**用户：**“编辑器保存后正常，打包运行时字幕没有显示。”

**智能体应执行：**结合保存证据记录 Editor 状态，再调查字幕设置、文字锚点、玩家作用域和资源，更新问题当前状态及游戏复现步骤。对尚未通过的打包场景保留未验证/失败结果，不沿用先前静态状态宣称成功。
