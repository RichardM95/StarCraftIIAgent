# 项目资料与运行数据

套件保存通用规则、工具、技能和参考；项目事实跟随项目资料目录，运行文件集中到 runtime/。

## 定位与初始化

运行 `python tools/project-paths.py` 只读取得资料、文档、账本、索引、报告与临时目录；不会创建它们。没有活动项目时项目路径为 null，参考索引使用套件旁 `<套件目录名>-data/reference/`。

`python tools/init-project.py "<主.SC2Mod>"` 默认记录主模组旁 `<模组名>.agent`。可用 `--project-data-dir "<目录>"` 指定其他位置；project.data_dir 的相对值以套件根目录解析，同盘优先保存相对路径。初始化只写本机配置，不建立资料空目录。

同一项目重新初始化保留明确的数据路径，切换项目重新推导；编辑副本保持所选主项目的数据归属。数据目录必须位于套件和 SC2Mod/SC2Map Components 之外。无效配置或写入失败直接报告，不回退套件 wiki/。

## 保存范围

| 内容 | 项目资料目录内位置 | 创建条件 |
|---|---|---|
| 项目设计 | docs/design/ | 有需持久保存的设计事实 |
| 机制约定 | docs/implementation/ | 有项目专属实现契约 |
| 设计来源 | docs/sources.md | 摄入项目设计材料 |
| 跨次问题 | docs/issues.md | 问题需要跨次跟踪 |
| 索引 | runtime/catalog/ | 实际构建时 |
| 游戏日志报告 | runtime/reports/bugreport.txt | 用户要求提取时 |
| 临时调查文件 | runtime/tmp/ | 需要文件暂存时 |

问题模板见 [模板](../../wiki/implementation/bug-reports/latest.md)。不为每次小修改新建账本或日志；主题直接描述当前约定，Git 与对话保留修改过程。项目文档可加入项目版本管理，runtime/ 不进入版本库。

默认构建/报告工具首次实际建立资料目录时排他创建仅含 runtime/ 的 .gitignore，已有文件保持原样。智能体首次保存项目文档也应沿用这一约定；若已有忽略文件未忽略 runtime/，提示用户或在授权范围内补充，不覆盖其规则。

Catalog 构建与查询共用默认路径，--out、--db、--graph 继续允许显式位置。临时检查其他主组件时其默认索引归属于该组件旁，查询使用显式索引位置。旧套件索引原地保留，可显式指定历史调查；首次需要新默认索引时重建。

`audit-issue-lifecycle.py --ledger "<文件>"` 检查明确账本；未指定时检查活动项目账本，尚未建立则显示 SKIP。显式缺失文件是错误。纯 docs scope 只检查套件文档/技能，mod 或完整检查包含项目账本审计。

历史备份、旧报告与旧索引不自动移动或删除；部署恢复文件继续遵循原工具位置约定。没有项目归属证据的资料保留，等待明确范围后处理。
